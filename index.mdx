Tiny Exchange exposes a strict REST and WebSocket trading surface in front of a
single-owner risk core. Use these docs to build clients, reason about fees, and
recover safely after disconnects or ambiguous responses.

<Warning>
The v8 API is a working draft for the bare-metal test phase. The Rust codec in
`protocol/external` defines the accepted bytes. The OpenAPI document describes
fields and behavior, but cannot express fixed JSON key order, whitespace bans,
or byte-identical retry rules.
</Warning>

## Source hierarchy

When sources disagree, use this order:

- `protocol/external` for canonical JSON parsing, encoding, and frame limits.
- `protocol/types/src/fees.rs` for fee arithmetic and rounding.
- `services/gateway/src/risk` for admission, balance, reserve, and fill policy.
- `api/external/openapi-*.yaml` for the trading and public market-data surfaces.
- These pages for integration guidance derived from those sources.

## Non-negotiable client rules

- Represent prices, quantities, balances, fees, and timestamps as integers. Never
  use floating-point money.
- Preserve the exact bytes of a submitted `new_order` until its `valid_until`
  deadline. A retry is the same bytes, not a reconstructed equivalent object.
- Treat HTTP `202` as durable submission, not execution or booking.
- Recover from a fresh snapshot before consuming a new live event stream.
- Deduplicate fills by `(market_id, book_seq, fill_index)` and apply absolute
  `remaining`, position, and balance values.
- Order only sequenced market events by `book_seq`. `ts_ms` is observational.

## Local preview

From the repository root:

```bash
npm install -g mint
mint dev
```

Run `mint validate` before publishing changes to the documentation or OpenAPI
draft.
